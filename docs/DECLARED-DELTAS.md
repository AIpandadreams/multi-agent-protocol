# Declared release deltas — `commands/wake.md`

This register records, by date, the places where the published `/wake` text DELIBERATELY differs from the
canonical deployment it was cut from. A row here means the difference is intended and will not be "fixed" by
a later reconciliation; a difference NOT recorded here is drift and is reconciled toward the canonical text.
Rows are appended, never edited; a delta that stops being deliberate gets a new row saying so.

| date | where (published text) | the published text | the canonical text it differs from | why the difference is deliberate |
|---|---|---|---|---|
| 2026-09-12 | header line 1, the protocol stamp | `[PROTOCOL v3.2]` | `[PROTOCOL v2.8]` | The stamp is a repo-identity field, not protocol text: it names the RELEASE this file belongs to. The canonical deployment carries its own protocol level and each keeps its own stamp. Merging it either way would mislabel one side's protocol level — the single most mechanical way a reconciliation could do damage. |
| 2026-09-12 | step 4, tier 1 — the parenthetical on `creator` | `creator` is canonical *"alongside the three positional roles"*; the resolver spans *"the full six-token seat space this command accepts — owner, builder, orchestrator, creator, engine, helper"*; *"one normalization contract with the step-6b digest"* | the same sentence cites a plan SCHEMA file's seat enum as the source of the six seats, and binds the normalization contract to the step-6b digest **and the renderer** | No schema file and no renderer ship in this release, so the published text states the six tokens inline as normative and drops the renderer from the contract. The canonical deployment HAS both, and there the schema is the authority and the renderer is bound by the same contract — that text is correct there and would dangle here. |
| 2026-09-12 | step 6a, daemon liveness — the scope rule | 6a runs only in a workspace whose `BINDINGS.md` binds a `CLOCK_DAEMON` row; a workspace without one skips 6a and its report's `Ledger:` block opens with `no clock daemon bound — clocks[] rows are unswept by machinery; the digest below is their only surfacing` | 6a is UNCONDITIONAL: every wake reads `plans/.daemon_heartbeat` and prints one of four `⛔ CLOCK DAEMON DOWN` lead lines when it is stale, absent, unparseable or future-dated | The clock-sweep daemon does not ship in this release (`docs/PLAN-LEDGER.md`), so an unconditional DOWN line would fire on every wake of every adopting workspace forever and train operators past a real alarm — the anti-pattern `CONTRIBUTING.md` records. The canonical deployment runs a daemon; there the unconditional check is a live alarm and is kept. ⚠ A deployment that adds a daemon must ALSO add the `CLOCK_DAEMON` binding, or its wakes will skip a check that has something to find. |
| 2026-09-12 | step 6b, open-ledger digest — the bulk of the paragraph | the three plan-file rules the digest relies on are stated INLINE and *"are normative in this file — no separate schema file ships"*; `owner` is *"REQUIRED on every step"*; a missing `owner` is *"a plan defect"*; the fired-clock rule is stated as a reason | the same paragraph cites the plan schema by name for each of those rules (`the frozen schema`, `schema FD-2`) | Same reason as row 2: no schema ships, so the rules a reader needs are stated where the reader is. The canonical deployment keeps its schema citations — it now ALSO carries the fired-clock REASON inline (merged from this text on 2026-09-12), so that one clause is no longer a delta. |
